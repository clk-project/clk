When you work on linked but separate projects — say a backend API and a
frontend app — changes in one often need to be verified in the other. If they
live in separate directories, you end up constantly ~cd~-ing back and forth,
losing context along the way.

clk projects scope their commands to directories: aliases, parameters and
scripts only activate when you're inside the project. That's great for
isolation, but painful when you need to jump between two or three repos in a
single workflow.

* The problem
  :PROPERTIES:
  :CUSTOM_ID: 683fcbea-b776-44ff-8af2-bb7e10a69bb0
  :END:

and want to rebuild the API, the command isn't there.

#+RESULTS[bdb754453d2d48d4dd67b47c95baa2b62c061b1b]: verbose-project

That works, but typing ~clk --project ../billing-api~ every time you switch
context gets old fast — especially when you're going back and forth several
times in a row.

* Global aliases
  :PROPERTIES:
  :CUSTOM_ID: 260d04a3-8c35-4581-8d40-e3479eb874a9
  :END:

This is where an alias to the root command helps. You can create a global alias
that points to ~clk~ itself, with the ~--project~ option baked in. Do this once
for each project.

#+NAME: leave-app
#+BEGIN_SRC bash :results none :exports code :session 55ed49b4-065d-440e-903b-658d1dcec014
cd ..
#+END_SRC

#+NAME: create-api-alias
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias set api clk --project ./billing-api
#+END_SRC

#+RESULTS[790ec28c9431c53e40d2f65fdf420f3d27ff4645]: create-api-alias
: New global alias for api: clk --project ./billing-api

#+NAME: create-app-alias
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias set app clk --project ./billing-app
#+END_SRC

#+RESULTS[74872c53ce36d9380c026c3eeb5c0cfc376ef446]: create-app-alias
: New global alias for app: clk --project ./billing-app

Subgroups and introspection commands work too. You can inspect either project's
aliases at any time.

* Local aliases
  :PROPERTIES:
  :CUSTOM_ID: 450ba117-403e-4bc3-a809-28d8a6f590c0
  :END:

The global approach is convenient but pollutes your top-level namespace. If you
only need cross-project shortcuts when you're actually working inside one of the
projects, local aliases are a cleaner fit. Each project declares its own
shortcut to the sibling, and nothing leaks outside.

First, let's remove the global aliases.

#+NAME: remove-global-api-alias
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias unset api
#+END_SRC

#+RESULTS[148d12a3901956002b23843b18861630d4fa00a6]: remove-global-api-alias
: Erasing api alias from global settings

#+NAME: remove-global-app-alias
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias unset app
#+END_SRC

#+RESULTS[586426e2c7d48fe1eae63aa5cbaa8beadc984fa9]: remove-global-app-alias
: Erasing app alias from global settings

* promoting an alias to the global profile
  :PROPERTIES:
  :CUSTOM_ID: promoting-an-alias-to-the-global-profile
  :END:

An alias you end up wanting everywhere need not be typed again elsewhere. From
~billing-api~, ~clk alias move~ carries ~build~ to the global profile as it
stands.

#+NAME: promote-build
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias move build global
#+END_SRC

#+RESULTS[]: promote-build
: Moved alias build, local -> global

It still answers here, now from the global profile rather than the local one.

#+NAME: promoted-build

clk build
#+END_SRC

#+RESULTS[]: promoted-build

And ~billing-app~ keeps the ~build~ of its own, which still wins over the one

* tidying up as the aliases pile up
  :PROPERTIES:
  :CUSTOM_ID: tidying-up-as-the-aliases-pile-up

Made in a hurry, aliases pile up and say nothing about themselves. Here is one
more, still in ~billing-app~, standing on the two you already have.

Were you setting things up from a script, you would rather it kept quiet. It

#+BEGIN_SRC bash :results none :exports code :session 55ed49b4-065d-440e-903b-658d1dcec014

#+END_SRC

Renaming is not only about the alias itself: the aliases that call it follow. It
reaches further than you asked for, so you may want to watch it happen before it
does. ~--dry-run~ says what it would do and writes nothing.

#+NAME: dry-run-rename
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk --dry-run alias rename test test-front
#+END_SRC

#+RESULTS[]: dry-run-rename
: Would have moved alias test -> test-front in local

#+NAME: show-before-rename
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias show
#+END_SRC

#+RESULTS[]: show-before-rename

: build echo Building the frontend
: ship build, test
: ship-all build, test, api build, api test
: ship-nightly build, test
: test echo Running frontend tests

Nothing moved, so now do it for real.

#+NAME: rename-test
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias rename test test-front
#+END_SRC

#+RESULTS[]: rename-test
: Moved alias test -> test-front in local

#+NAME: show-after-rename

Had one of them lived in a profile clk cannot write to, it would have warned you
that the old name is still used there, for you to correct by hand.

Not every name will do, though. Start one with a dash and your shell would hand
it to clk as an option, so clk turns it down before you get there.

#+NAME: dash-alias
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias set -ship build
#+END_SRC

#+RESULTS[]: dash-alias
: Usage: clk alias set [OPTIONS] ALIAS COMMAND [PARAMS]...
: error: Aliases must not start with dashes (-)

Begin it with punctuation instead and it tells you what a name may start with.

#+NAME: punctuation-alias
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias set ,ship build
#+END_SRC

#+RESULTS[]: punctuation-alias
: error: Invalid alias name: ,ship. An alias must start with a letter, a digit or an underscore

You see every alias from here, but you only write to one profile at a time. Put
one in the global profile and then forget where it lives.

#+NAME: global-alias
#+BEGIN_SRC bash :results none :exports code :session 55ed49b4-065d-440e-903b-658d1dcec014
clk alias --global set deploy-prod echo Deploying to production
#+END_SRC

#+NAME: document-elsewhere
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes
clk alias set-documentation deploy-prod "Ship to production"
#+END_SRC

#+RESULTS[]: document-elsewhere
: error: The profile local has no 'deploy-prod' alias registered. Try using another profile option (like --local or --global)

Dropping it from here gets the same answer.

#+NAME: unset-elsewhere
#+BEGIN_SRC bash :results verbatim :exports both :session 55ed49b4-065d-440e-903b-658d1dcec014 :cache yes

#+END_SRC
